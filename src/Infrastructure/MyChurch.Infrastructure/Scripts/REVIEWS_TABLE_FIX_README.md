# Fix para Error: 42P01 - relação "Reviews" não existe

## ?? Problema

A migration `20251002191730_AddReviewsTable` estava vazia (no-op), mas migrations subsequentes dependem da tabela `Reviews`:
- `20251003171804_AddReviewVotesTable` - cria foreign key para Reviews
- `20251003180339_AddReviewPhotosTable` - cria foreign key para Reviews
- `20251003182958_AddReviewResponsesTable` - cria foreign key para Reviews

Quando você tenta aplicar essas migrations, o PostgreSQL retorna o erro:
```
Npgsql.PostgresException (0x80004005): 42P01: relação "Reviews" não existe
```

## ? Solução

### Opção 1: Executar Script SQL Manual (RECOMENDADO)

Este é o método mais seguro se você já tem dados no banco.

#### Windows PowerShell:
```powershell
# Na raiz do projeto
.\Infrastructure\MyChurch.Infrastructure\Scripts\FixReviewsTable.ps1

# Ou especifique a connection string:
.\Infrastructure\MyChurch.Infrastructure\Scripts\FixReviewsTable.ps1 -ConnectionString "Host=localhost;Port=5432;Database=mychurch_db;Username=postgres;Password=SuaSenha"
```

#### Executar manualmente via psql:
```powershell
psql -h localhost -U postgres -d mychurch_db -f Infrastructure\MyChurch.Infrastructure\Scripts\FixReviewsTableMigration.sql
```

#### Executar via SQL client (pgAdmin, DBeaver, etc):
Abra o arquivo `Infrastructure\MyChurch.Infrastructure\Scripts\FixReviewsTableMigration.sql` e execute-o.

### Opção 2: Reset Completo do Banco (ATENÇÃO: Perde todos os dados)

Se você está em desenvolvimento e pode perder os dados:

```powershell
# 1. Dropar o banco
psql -U postgres -c "DROP DATABASE IF EXISTS mychurch_db;"

# 2. Recriar o banco
psql -U postgres -c "CREATE DATABASE mychurch_db;"

# 3. Aplicar todas as migrations novamente
dotnet ef database update --project Infrastructure\MyChurch.Infrastructure --startup-project Web\MyChurch.Api.Web
```

### Opção 3: Remover Migration History Entry

?? **Avançado**: Só use se entender o que está fazendo!

```sql
-- 1. Remover a migration vazia do histórico
DELETE FROM postgres.__efmigrationshistory 
WHERE migration_id = '20251002191730_AddReviewsTable';

-- 2. Executar o script de correção
-- (executar FixReviewsTableMigration.sql)

-- 3. Adicionar a migration de volta ao histórico
INSERT INTO postgres.__efmigrationshistory (migration_id, product_version)
VALUES ('20251002191730_AddReviewsTable', '9.0.3');
```

## ?? Verificação

Após aplicar a correção, verifique se a tabela foi criada:

```sql
-- Verificar se a tabela existe
SELECT table_name 
FROM information_schema.tables 
WHERE table_schema = 'public' 
  AND table_name = 'Reviews';

-- Verificar a estrutura da tabela
\d "Reviews"

-- Verificar as migrations aplicadas
SELECT * FROM postgres.__efmigrationshistory 
ORDER BY migration_id;
```

## ?? Aplicar Migrations Restantes

Depois de corrigir a tabela Reviews:

```powershell
dotnet ef database update --project Infrastructure\MyChurch.Infrastructure --startup-project Web\MyChurch.Api.Web
```

## ?? O que foi corrigido

1. **Arquivo atualizado**: `Infrastructure\MyChurch.Infrastructure\Migrations\20251002191730_AddReviewsTable.cs`
   - Antes: Migration vazia (no-op)
   - Depois: Cria a tabela Reviews com todas as colunas e relacionamentos

2. **Scripts criados**:
   - `FixReviewsTableMigration.sql` - Script SQL para criar a tabela manualmente
   - `FixReviewsTable.ps1` - Script PowerShell para executar a correção automaticamente

## ?? Estrutura da Tabela Reviews

```sql
CREATE TABLE "Reviews" (
    "Id" integer PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY,
    "EntityId" integer NOT NULL,
    "EntityType" varchar(50) NOT NULL,
    "ReviewerId" integer NOT NULL,
    "Score" integer NOT NULL,
    "Comment" varchar(1000) NOT NULL,
    "CreatedAt" timestamp NOT NULL,
    "IsVerified" boolean NOT NULL DEFAULT false,
    "WorshipPresenceId" integer NULL,
    "VerifiedAt" timestamp NULL,
    FOREIGN KEY ("ReviewerId") REFERENCES postgres.member(id),
    FOREIGN KEY ("WorshipPresenceId") REFERENCES postgres.worship_presences(id)
);
```

## ?? Prevenção Futura

Para evitar esse tipo de problema:

1. ? Sempre rode `dotnet ef migrations add` em ambiente limpo
2. ? Verifique o conteúdo das migrations antes de commit
3. ? Teste migrations em banco de desenvolvimento antes de produção
4. ? Use `dotnet ef database update` regularmente durante desenvolvimento
5. ? Nunca deixe migrations vazias ou comentadas

2. Confirme que o PostgreSQL está rodando
3. Verifique se tem permissões no banco
